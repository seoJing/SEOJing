# 관리자 글 읽기 지표 계약

`/ops/analytics`의 읽기 성과는 수집된 `seojing.analytics.v1` 이벤트로만 계산한다. 수집 URL 또는 origin summary가 연결되지 않았거나 조회 이벤트가 없으면 숫자 `0%` 대신 측정 불가 상태를 표시한다. Cloudflare Web Analytics의 방문 수와 이 화면의 조회 세션은 정의가 다르므로 합산하지 않는다.

## 지표

| 지표               | 분자 / 분모                                                                        | 용도                              |
| ------------------ | ---------------------------------------------------------------------------------- | --------------------------------- |
| 조회 세션          | 같은 UTC 날짜·글 slug·브라우저 `session_id`에서 `post_view`가 하나 이상인 묶음     | 글별 읽기 기회 규모               |
| 깊이 읽기 비율     | 조회 세션 중 `scroll_depth.max_depth_percent >= 75`가 있는 묶음 / 조회 세션        | 본문 하단까지 도달했는지의 근사치 |
| 능동 상호작용 비율 | 조회 세션 중 목차 이동, 코드 복사, Q&A 답변 확인, TTS 재생이 있는 묶음 / 조회 세션 | 읽기 외 기능의 실제 사용          |

같은 세션의 반복 이벤트와 동일 `event_id` 재전송은 한 번만 센다. `post_view`가 없는 고아 상호작용은 분자와 분모에서 제외한다. 이벤트 발생일이 아닌 **서버 수신일**로 당일을 포함한 최근 30개 UTC 날짜를 집계한다. 현재 날짜는 미완성 구간이므로 전일과 직접 비교하지 않는다.

`session_id`는 집계 과정에서만 사용하고 응답에는 넣지 않는다. 이는 고유 사람 수가 아니며, 다른 브라우저·탭이나 날짜를 아우르는 사용자를 식별하지 않는다. 스크롤 75%는 완독을 증명하지 않고, 상호작용 비율은 만족도 지표가 아니다. 글별 표본이 작을 때 비율 변동은 해석하지 않는다. 콘텐츠 변경 효과를 판단할 때는 **완결된 같은 길이의 기간**, 유입량과 글별 조회 세션 수를 함께 비교한다.

TTS 플레이어가 전송하는 세부 상태는 수집 시 허용된 형태인지 검사하되, 저장 이벤트에는 `action`, `artifact_kind`, 유효한 `playback_rate`만 남긴다. 이는 사용 여부를 계산하는 데 불필요한 아티팩트 식별자·재생 위치를 장기 보관하지 않기 위한 경계다.

## 운영 연결 확인

1. `SEOJING_ANALYTICS_COLLECT_URL`이 설정된 배포에서 실제 글 조회 후 collect가 `disabled:true`가 아닌지 확인한다.
2. Origin의 저장·요약 API와 `/ops/analytics`의 `SEOJING_ANALYTICS_OPS_SUMMARY_URL`을 연결한다. `/ops/*`는 Cloudflare Access 뒤에 둔다.
3. 관리자 화면에 조회 세션이 나타나는지 확인한다. 점검 방문은 기준선에서 별도로 기록한다.

현재 운영 연결이 완료되기 전에는 이 화면으로 방문·읽기 성과를 주장하지 않는다. 다음 단계의 목록→글 클릭률은 목록 노출과 클릭을 별도 계측한 뒤 같은 화면에서 계산한다. 현재 `post_view`를 클릭 수로 부르지 않는다.
